# Universal Robot Controller 🤖📱

Приложение для Android, предназначенное для удаленного управления робототехническими платформами на базе ESP8266/ESP32. Обеспечивает FPV-управление с низкой задержкой, динамическую конфигурацию оборудования и мониторинг сенсоров в реальном времени.

## 🛠 Технологический стек

| Категория | Технологии |
| --- | --- |
| **Язык** | Kotlin |
| **UI** | Jetpack Compose (Material3) |
| **Архитектура** | MVVM (Model-View-ViewModel) |
| **DI** | Dagger Hilt |
| **Асинхронность** | Coroutines & Flow |
| **Сеть** | Java-WebSocket, UDP DatagramSocket, HttpURLConnection |
| **Мин. версия** | Android 10 (API 29+) |

## 🚀 Основные возможности

* **Автоматическое обнаружение:** Приложение самостоятельно находит робота и камеру в локальной сети, не требуя ручного ввода IP-адресов.
* **FPV (First Person View):** Трансляция видеопотока с камеры (ESP32-CAM) с минимальной задержкой.
* **Умное управление моторами:** Поддержка дифференциального привода (танковая схема) и обычного управления с защитой от "флуда" командами (Throttling).
* **Динамическая конфигурация:** Встроенный редактор пинов позволяет переназначать порты микроконтроллера прямо из приложения без перепрошивки устройства.
* **Двусторонняя связь:** Отображение данных с сенсоров, статуса подключения и логов в реальном времени.

## 📱 Интерфейс пользователя

Приложение адаптируется под ориентацию устройства, предоставляя оптимальный интерфейс для различных сценариев использования.

### 1. Панель управления (Dashboard)

Основной экран для управления роботом.

**Книжная ориентация (Portrait):**
Удобна для диагностики и настройки.

* Сверху: Статус подключения и кнопка включения камеры.
* Центр: Сетка показателей сенсоров и кнопки управления периферией (свет, реле).
* Снизу: Видеопоток (если включен) и панель управления моторами.

**Альбомная ориентация (Landscape):**
Предназначена для активного FPV-управления.

* Полноэкранный режим (Immersive Mode).
* Видеопоток на заднем плане.
* HUD-интерфейс: Показания сенсоров на полупрозрачной верхней панели.
* Виртуальные джойстики для удобного управления двумя руками.

### 2. Редактор Пинов (Pin Editor)

Инструмент для назначения физических пинов контроллера виртуальным устройствам.

* Визуальное отображение платы (Wemos D1 Mini).
* Поддержка локальных (ESP) и удаленных (RS485/Arduino Uno) устройств.
* Типы устройств: `Motor`, `LED`, `Sensor`.

## 📡 Логика соединения

Приложение использует гибридную схему подключения для обеспечения максимальной скорости и удобства.

1. **UDP Discovery (Порт 4210):**
* Приложение слушает широковещательные UDP пакеты.
* Ожидает сигнатуры: `I_AM_ROBOT:<IP>` для контроллера и `I_AM_CAMERA:<IP>` для видео-модуля.
* Это позволяет автоматически переподключаться при смене IP-адреса, выданного роутером.


2. **WebSocket (Порт 81):**
* Основной канал управления роботом.
* Используется персистентное соединение с Heartbeat-механизмом (пинг каждые 3 секунды).
* Реализован автоматический реконнект с экспоненциальной задержкой (Backoff) при обрыве связи.


3. **MJPEG Stream (Порт 81, HTTP):**
* Видеопоток с камеры запрашивается по отдельному HTTP-каналу.
* Используется кастомный парсер MJPEG (`MjpegInputStream`) и отрисовка через `SurfaceView` для исключения задержек буферизации, свойственных стандартным плеерам.

## 🔌 API и Протокол команд

Обмен данными происходит в формате JSON. Реализована система троттлинга (ограничения частоты) для моторов, чтобы не перегружать канал (макс. 30 пакетов/сек).

### 1. Управление моторами

**Установка скорости (одиночный мотор):**

```json
{
  "cmd": "action",
  "device": "left_motor",  // Имя устройства, заданное в PinEditor
  "action": "set_speed",
  "value": 255             // Значение от -255 до 255
}

```

**Троттлинг:** Приложение автоматически фильтрует незначительные изменения джойстика (мертвая зона +/- 4) и объединяет пакеты при частом изменении скорости.

### 2. Управление периферией (LED, Реле)

```json
{
  "cmd": "action",
  "device": "headlight",
  "action": "on"  // или "off"
}

```

### 3. Работа с сенсорами

**Подписка на обновления:**
При открытии экрана приложение подписывается на нужные датчики:

```json
{
  "cmd": "subscribe",
  "device": "battery_sensor"
}

```

**Входящие данные от робота:**

```json
{
  "cmd": "sensor_update",
  "device": "battery_sensor",
  "value": 12.4
}

```

### 4. Конфигурация и статус

**Запрос списка устройств:**

```json
{ "cmd": "get_devices" }

```

**Ответ робота:**

```json
{
  "devices": [
    { "name": "motor_l", "pin": 5, "type": "motor", "state": 0 },
    { "name": "led_main", "pin": 2, "type": "led", "state": true }
  ]
}

```

### 5. Board Info (системная информация)

При подключении робот присылает информацию о плате:

```json
{
  "cmd": "board_info",
  "board": "ESP8266",
  "chip_id": "00112233"
}

```
